# Design: voice recorder with translation

Status: first version, built but not yet run on hardware.
Owner: Colson (`coobytron`).

## What it does

Hold the front button and speak. Let go, and the stick uploads the clip, gets a transcript, translates it into the target language, and shows the translation on screen with the original underneath. The side button picks the target language.

## Hardware facts this relies on

| Part | M5StickC Plus 1.1 | Consequence |
|---|---|---|
| SoC | ESP32-PICO-D4, 520 KB SRAM, no PSRAM, 4 MB flash | Audio cannot be buffered in RAM (~100 KB usable means ~3 s). Record to flash instead. |
| Microphone | SPM1423 PDM mic, CLK G0, DATA G34 | Read through `M5.Mic` from M5Unified, which knows the pins. |
| Display | 1.14" ST7789, 135 x 240 | Landscape 240 x 135, 14 px font: about 7 lines of text. |
| Buttons | A (front, G37), B (side, G39), power (AXP192) | Three inputs; mapping below. |
| Storage | No SD slot | WAV goes to LittleFS on internal flash. |

## Pipeline

```text
 hold A            release A           WiFi / HTTPS                         screen
┌────────┐  PCM  ┌──────────────┐  ┌────────────────────────┐  text  ┌──────────────────┐  text  ┌─────────┐
│ PDM mic├──────►│ /rec.wav on  ├─►│ OpenAI transcriptions  ├───────►│ Claude Messages  ├───────►│ display │
│ 16 kHz │       │ LittleFS     │  │ (whisper-1)            │        │ API: translate   │        │         │
└────────┘       └──────────────┘  └────────────────────────┘        └──────────────────┘        └─────────┘
```

1. **Record.** 16 kHz, 16-bit mono (32 KB/s). Three 100 ms buffers rotate through `M5.Mic.record()`; each finished buffer is appended to `/rec.wav`. The 44-byte WAV header is patched with the real length on stop.
2. **Transcribe.** `POST https://api.openai.com/v1/audio/transcriptions`, multipart, `model=whisper-1`, `response_format=verbose_json`. The file is streamed from flash, never loaded into RAM. Returns the text and the detected spoken language.
3. **Translate.** `POST https://api.anthropic.com/v1/messages` with the transcript and a short system prompt ("translate into X, reply with only the translation"). Model `claude-opus-5-5`, `effort: low`, server-side fallback on refusals enabled.
4. **Show.** Translation in large text, then "Heard (language): transcript" in grey. Scroll with the power button.

### Why two services

Claude does not take audio input, so speech-to-text needs a dedicated model. Whisper is the most widely used hosted option with a simple multipart API. Claude does the translation, which keeps tone and idiom better than word-for-word engines and lets the target language be any name you type in `config.h`.

Both are behind one interface (`src/cloud.h`), so either can be swapped later (for example, a local Whisper server on your LAN for privacy).

### Why the device calls the APIs directly

A first version without a relay server has fewer moving parts. The cost is that API keys live in the firmware (`include/secrets.h`, git-ignored). If the stick is shared or lost, rotate the keys. A relay is listed under "Later".

## Controls

| Input | Idle / result screen | While recording |
|---|---|---|
| Hold A | Start recording | Keep recording |
| Release A | — | Stop, then transcribe and translate |
| Click B | Next target language. On the result screen this re-translates the last transcript, no new upload needed. | — |
| Click power | Scroll the result down (wraps to top) | — |
| Hold power 6 s | Power off (hardware) | — |

The target language is saved in NVS and survives reboots.

## Limits

- **Clip length:** 20 s by default (`MAX_RECORD_SECONDS`), also capped by free LittleFS space (the `huge_app` partition table leaves about 900 KB, roughly 28 s).
- **Fonts:** one Japanese efont is used for every language except Chinese, which uses the Chinese efont. Korean, Arabic, Hindi, Thai and other scripts are not in either font and would render as blanks, so they are not in the default language list.
- **Latency:** upload time is roughly clip length divided by WiFi throughput, plus two API round trips. Expect a few seconds for a short phrase on good WiFi. Not measured yet.
- **Offline:** nothing works without WiFi. Recording works, the upload step reports the error.

## Security and privacy

- Keys are compiled in from `include/secrets.h`, which is git-ignored. `include/secrets.example.h` is the template.
- TLS is verified against a pinned set of public root CAs (`src/ca_roots.h`, regenerated by `tools/make_ca_roots.py`). If a provider changes CA and the handshake fails, regenerate the file.
- Audio goes to OpenAI and text goes to Anthropic. Both providers' data policies apply. The WAV is overwritten on the next recording and is never kept on the device beyond that.
